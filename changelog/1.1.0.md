# 1.1.0

The first release after 1.0.0, and an additive one — every change here is a new component, a new prop, or a bug fix.

Two threads run through it. The first is **touch**: dragging a Slider on a phone would let the page scroll out from under your finger, and the same bug lived in the Knob, the Rating row and the Waveform. That is now one shared gesture core rather than four near-identical PanResponders, and the new `Joystick` is built on it. The second is **navigation**: `Tree` learned what "the current page" means, and `NavTree` turns a flat route list into a real sidebar on top of it.

Alongside those, a batch of mobile-web overlay fixes — menus and dropdowns landing a keyboard's height away from where they belong — and a `Grid` rewrite that makes gutters behave.

There are three small removals and one widened type, collected under **Migration notes**.

## New components

- **`RollingNumber`** — an animated number readout that rolls each changed digit into place, leaving unchanged digits still. Handles prefix/suffix, thousands separators and fixed decimals, with a configurable duration and timing function.
- **`Joystick`** — a two-axis stick and XY pad input, with a dead zone, optional stepping, axis locking, `shape` (`circle` / `square`) and `variant` styling, and full keyboard support. Emits a `JoystickValue` of normalized `x`/`y`.
- **`NavTree`** — turns a flat list of routes into a nested sidebar. It groups and orders items by each one's category, opens the branches above the current page, marks and scrolls to it, remembers which branches were left open, and collapses to a rail of top-level icons.
  - `searchable` adds a filter field over the tree, with matched substrings marked.
  - Rows carrying an `href` render as real `<a>` elements on web, so cmd-click, middle-click, "copy link address" and crawlers all work while plain clicks still route client-side.
  - `buildNavTree` is exported for callers that want the nesting logic without the component.

## A shared gesture core

`Slider`, `RangeSlider`, `Knob`, `Rating` and `Waveform`'s scrub each carried their own PanResponder, and each had the same two bugs.

On **web**, react-native-web registers its `touchmove` listener on `document` without `{ passive: false }`, so every `preventDefault()` those components called was a silent no-op in every modern browser — a few pixels of cross-axis drift and the browser claimed the touch as a scroll. On **native**, a PanResponder inside a `ScrollView` hands the gesture back unless it explicitly refuses; iOS took the touch as soon as it looked like a pan, and Android never received the `requestDisallowInterceptTouchEvent` that would make the scroll view stand down.

A third bug rode along on both: value was derived from `locationX`/`locationY`, which are relative to *whatever view the touch is currently over*. Once the pointer left the control, the mapping drifted.

`src/core/gestures` fixes all three in one place, and is exported for app code building its own drag surfaces:

| Export | Job |
| --- | --- |
| `useDragGesture` | The whole thing: surface-relative coordinates measured once per gesture from `pageX`/`pageY`, both locks, and termination/unmount cleanup. |
| `getGestureSurfaceStyle` | `touch-action` on the surface, plus selection / callout / tap-highlight suppression. The load-bearing piece on web. |
| `GESTURE_RESPONDER_LOCK` | `onPanResponderTerminationRequest: false` + `onShouldBlockNativeResponder: true`, to spread into a `PanResponder.create` config. |
| `acquirePageScrollLock` / `releasePageScrollLock` | Ref-counted, web-only. Sets `overscroll-behavior: none` and registers a genuinely non-passive `touchmove` blocker. |
| `acquireTextSelectionLock` / `releaseTextSelectionLock` | Ref-counted `user-select: none`, so a mouse drag doesn't highlight the page it sweeps over. |

`Slider`, `RangeSlider`, `Knob`, `Rating`, `Joystick` and `Waveform` are built on `useDragGesture`. `NumberInput`'s drag-scrub keeps its own responder but now takes the page-scroll lock once the scrub clears its activation distance, releases it on unmount, and blocks the enclosing native scroll view for the rest of the gesture.

`axis` picks the `touch-action` value and is a real trade — a surface that claims a direction is a surface the page can't be scrolled from. Compact controls use `both`; large scrub surfaces like `Waveform` claim one axis and leave the other to the page.

## `Tree` learned about navigation

`Tree` had selection but no notion of "you are here", which is a different thing — a sidebar's current page isn't a selection the reader made.

- **`activeId`** marks the row representing the current location, opens the branches above it, and scrolls it into view, all without consuming `selectedIds`.
- **`activeHref`** does the same by matching a node's `href` instead. Hand it a pathname and the tree finds the row.
- **`expandToActive`** (default `true`) opens the branches leading to the active node when it changes. Re-opening is keyed on the ancestor set, so a branch the reader collapsed stays collapsed while they move between its children.
- **`scrollActiveIntoView`** (default `true`, web only).
- **`persistKey`** remembers which branches are open across reloads via `localStorage`. Ignored while expansion is controlled through `expandedIds` — in that mode the parent owns the state.
- **`useTreeState`** is now exported, for callers driving a tree's expansion themselves.
- `TreeNode.href` rows render as real `<a href>` anchors on web; native falls back to a pressable with the `link` role.
- `TreeNodeState` gained an `active` field alongside `selected`.

## Overlays on mobile web

Menus and dropdowns that opened *upward* landed roughly a keyboard's height below where they belonged.

The overlay renderer applies a `bottom` pin as CSS on a `position: fixed` element, which the browser resolves against the **layout** viewport. The pin was being computed from `Dimensions.get('window')`, which react-native-web sources from `visualViewport` — a height that shrinks when the on-screen keyboard opens. Anchor rects come from `getBoundingClientRect`, which is layout-viewport coordinates, so mixing the two dropped every upward-opening overlay by exactly the difference. Bottom pins now resolve against `document.documentElement.clientHeight`.

Three components had their own version of the same class of problem:

- **`Select`** — in mobile picker (Modal) mode the options render as a centered dialog card, not an anchored dropdown, so sizing them to the trigger's width left a narrow list floating at the screen's left edge. The card now takes a comfortable dialog width. On every platform, an explicitly resolved dropdown width now also sets `maxWidth`, so the 320px cap in `menuStyles.dropdown` can no longer shrink a dropdown below a trigger that's wider than it.
- **`AutoComplete`** — the mobile picker is now pinned to the top of the screen rather than centered. The modal autofocuses its input, so the keyboard is up the whole time it's open, and a centered dialog put the suggestion list exactly where the keyboard was. Its height accounts for safe-area insets and, when a `KeyboardManagerProvider` is mounted, the keyboard itself.
- **`Menu`** — `w="auto"` now means auto: the panel is as wide as its longest item and no wider, hugging the same edge its placement anchored to, and never narrower than the trigger it hangs off.

## `Grid`

`Grid` built its gutters from negative container margins and per-cell padding, which meant percentage widths that no longer fit once a real gap sat between them.

Children are now packed into rows up front, so gutters are plain `rowGap` / `columnGap` on the containers. Each cell carries the gaps a multi-track span swallows in its `flexBasis`, leaving the grow ratio to split bare track width only — so a cell measures exactly `span * track + (span - 1) * gap`, and the tracks line up across every row whatever mix of spans a row happens to hold. Short rows hold their unused tracks open with a spacer instead of stretching.

`rowGap` and `columnGap` of `0` are now respected; they previously fell back to `gap` because the check was truthiness rather than `undefined`.

## Fixes

- **The dark-mode flash is gone.** `ThemeModeProvider` hardcoded the system scheme to light on web and only corrected it in a post-paint effect, so an auto-mode load painted a light frame before flipping dark. `useColorScheme` is now a `useSyncExternalStore` over `matchMedia`/`Appearance`: hydration still matches the server HTML, then React re-renders with the real scheme before first paint. The persisted mode is gated the same way, so the hydration pass stays clean.
- **Optional dependencies are optional again under Metro.** The `optionalModule` loader map called `require()` outside any lexical try/catch, and `Masonry`, `Carousel`, `DataTable`, `GradientText` and `ShimmerText` imported their engines statically — so Metro treated all ~14 optional packages as hard dependencies and failed the whole app bundle when any was missing. Each registered require is now wrapped in its own try/catch (which Metro's `allowOptionalDependencies` recognizes), and the five components resolve their engines lazily with real fallbacks: `Masonry` renders non-virtualized columns, `DataTable`'s virtual mode downgrades to a plain table, `Carousel` warns and renders nothing, `GradientText` falls back to solid-color text, and `ShimmerText` renders without the shimmer overlay.
- **`Input`'s 400px minimum width no longer overflows a narrow parent.** `min-width` outranks both `width` and `max-width`, so a field inside a 420px sign-in card pushed past the card's own padding. Web clamps the floor with CSS `min(100%, 400px)`; Yoga has no equivalent, so native keeps the plain floor (and mobile, as before, skips it entirely).
- **`HeatmapChart` hover no longer double-draws its labels.** Hovering stacked a second, larger label over the one the cell already drew. Hover now grows the cell's own label instead, capped by the cell's height so it can't spill into its neighbours, with the baseline re-centred as the glyphs grow. Cells without a permanent label still reveal their value on hover, which is what the old overlay existed for.

## Additions

- **`CodeBlock` highlights shell.** Every language that wasn't JavaScript-shaped fell through to the JS grammar, so a `bash` block came out about as colored as plain text. There's now a shell grammar covering commands, flags, strings, variables, comments, pipes and redirects, used for `bash` / `sh` / `zsh` / `shell` / `shellscript` / `console` / `terminal` blocks and for every `variant="terminal"` block. Those aliases are also recognized by `normalizeLanguage`, and `isShellLanguage` is exported.
- **Twelve new brands** in `BrandIcon` and `BrandButton`: `anthropic`, `threads`, `bluesky`, `pinterest`, `snapchat`, `wechat`, `expo`, `react`, `nodejs`, `stripe`, `apple-pay` and `google-pay`. `apple-podcasts` and `amazon-music` were corrected to their official brand colors.
- **`IconButton` takes `color`**, matching `Button`, `Badge`, `Chip` and `Card`. `filled`, `secondary` and `outline` tint the container; `ghost` and the neutral `default`/`none` keep their chrome and tint only the icon; `gradient` draws its own overlay and ignores it. `colorVariant` still works as a deprecated alias — `color` wins when both are set.
- **`AudioPlayer` is exported from the package root.** It was reachable from its `@platform-blocks/react-ui-library/AudioPlayer` subpath but missing from the main entry point. `AudioPlayerProps` and `AudioPlayerRef` are exported too.
- **Types that existed but weren't exported** now are: `SelectOption`, `AutoCompleteOption`, `AccordionItemType`, `TreeNodeState`.

## Docs and tooling

- The site's sidebar is now a `NavTree`, replacing the hand-rolled `NavigationSection`.
- **Expo Snack integration.** Every demo opens in a Snack that pulls the published package from npm, with a light/auto/dark switch at the top so you can watch the whole thing re-theme — the one thing a screenshot on the docs site can't show.
- The getting-started page covers the starter templates (`expo-template`, `expo-min-template`, `native-template`, `universal-template`, `web-template`, `extension-template`), with a new `PrerequisitesList`.
- An extensions registry page, an examples gallery, and a starter-templates rail.
- `llms.txt` is an index plus per-page Markdown rather than one file — 27.5 KB index, 152 per-page files, and a 1.2 MB full text for tools that want everything.
- **Agent skills** are generated from the component metadata (`npm run skills:generate`), with `npm run skills:check` wired into `verify:packages` to keep them from drifting.
- `@platform-blocks/charts` no longer type-checks its demo fixtures during the declaration build. The demos import the package by name (so they can be copied straight out of the docs), which the package's own build can't resolve — this mirrors what `@platform-blocks/react-ui-library` already did, and drops 352 build warnings along the way.

## Migration notes

**`EmojiPicker` was removed.** `EmojiPicker`, `EmojiPickerProps` and the `EmojiPickerVariant` type are gone. There's no drop-in replacement; the component was a thin `quick`-variant reaction row, and a `Menu` or `Popover` of `Button`s reproduces it in a few lines.

**Two brand names were removed:** `chrome-web-store` and `amazon-appstore`. If you were using either — including via the badge shells listed in the 1.0.0 migration table — pass `brand="chrome"` or `brand="amazon"` and set `primaryText` / `secondaryText` yourself.

**`CodeBlockColorOverrides.highlight.accent` was removed.** It was declared but never read; the highlight band is drawn from `highlight.background` alone. Delete the key — TypeScript will point at it.

**`TreeNodeState` gained a required `active` field.** Only affects code that *constructs* a `TreeNodeState` object; a custom `renderNode` that reads the state is unaffected.

```bash
npm install @platform-blocks/react-ui-library@1.1.0 @platform-blocks/charts@1.1.0
```
