# 1.2.0

Three themes: **there is now a single color prop**, **every style prop has one short name**, and **charts fit the space they are given.**

Six prop names had accumulated for what was largely one job — `color`, `c`, `colorVariant`, `sev`, `tone`, and a `colorScheme` that meant "palette" on two components and "light or dark" on two others. `colorVariant` alone carried four incompatible contracts across the eight components that accepted it, and the split was hiding real bugs: on `Text`, `c="error"` and `color="error"` rendered *different colors*.

**This release is breaking, on purpose.** The old spellings are gone rather than deprecated — the library is new enough that carrying a compatibility layer would cost more than the migration does. A codemod rewrites the color props; the style-prop renames are listed below in full.

The second is brevity. Text styling, sizing, and backgrounds now use the short names Mantine uses — `c`, `fw`, `lts`, `tt`, `w`, `maw`, `bg` — and they are the *only* names: the long spellings are removed, not aliased. The box props (`w`, `h`, `miw`, `maw`, `mih`, `mah`, `bg`, `opacity`) now work on every component. [Jump to it](#short-style-props).

The third theme is `@platform-blocks/charts`, which stopped drawing at fixed pixel sizes: a chart now measures its container, fills it, and reserves margins from the labels it is about to draw rather than from a constant. [Jump to the charts sections](#charts-fit-the-space-they-are-given).

A smaller, visual change rides along: **titles and group labels step back from the items they label**, through two theme text roles. [Jump to it](#titles-step-back-from-what-they-label).

## `color` is the prop

`color` — `c` on the text components — now accepts the full vocabulary on every component:

| Form | Example | Resolves to |
| --- | --- | --- |
| Palette token | `color="success"` | that palette, at the shade the context calls for |
| Palette + shade | `color="primary.6"` | exactly that shade |
| Text role | `c="muted"` | `theme.text.muted` |
| Background token | `color="border"` | `theme.backgrounds.border` (Divider) |
| Any CSS color | `color="#2563EB"` | itself |

One helper resolves all of it: `resolveColorProp` in `core/theme`, with `resolveTextColor` / `resolveBg` / `resolveAccentColor` / `resolveLineColor` pinning the shade and token vocabulary per context. It is exported, so app code building its own components can resolve a color prop the way the library does. It replaces roughly a dozen near-identical private resolvers that had each drifted to a different shade default.

`ThemeColor` is exported alongside it and is now the type of every color prop — a palette token, `primary.6` shade syntax, or any CSS color, with editor completion for the tokens. It replaces `AlertColor`, `ToastColor`, `ProgressColor`, and `AccordionColor`, which had drifted apart (`AccordionColor` alone included `tertiary`).

## Colors that were silently discarded

`color` accepted a raw CSS color on Button, Badge, and Chip — and quietly threw it away on nine other components, which looked the value up as a palette key, got `undefined`, and fell back to primary. `<Switch color="#FF0000">` rendered blue. So did `<Switch color="primary.2">`.

Every one of these now takes the full vocabulary, at the shade it already used for bare tokens — so nothing that works today moves:

| | Was accepted | Silently dropped |
| --- | --- | --- |
| `Switch` | 6 bare palette names | raw colors, shade syntax, aliases |
| `Progress` | bare names, `#hex` | `rgb()`/named colors, shade syntax, aliases |
| `Waveform` | 6 hard-coded names | every other palette, shade syntax, aliases |
| `Tabs` | bare names | raw colors, shade syntax, aliases |
| `Accordion` | bare names | raw colors, shade syntax, aliases — fell back to **gray** |
| `Gauge`, `Link`, `IconButton`, `CodeBlock` | bare names, raw colors | shade syntax, aliases |

A cross-component contract test now asserts this table rather than trusting it.

`Pagination` and `KeyCap` still take only palette names — they index several shades of one ramp, which a single color can't supply. Their types say so.

## Fixed along the way

- **`Text`: `c` and `color` disagreed.** `c` resolved a bare palette name to shade 6 and `color` to shade 5, so the same token rendered as two different colors depending on which spelling you reached for. Both now resolve at shade 6 — the higher-contrast neighbour of the base in *both* light and dark, since palettes invert between schemes. `color="success" | "warning" | "error"` on `Text` shifts one shade darker in light mode and one lighter in dark; every other value is unchanged.
- **`Toggle`: precedence was inverted.** `colorVariant` overrode `color`, the opposite of every other component. A `ToggleButton`'s own color also lost to its group's; the child now wins, as it does for `variant`, `size`, and `disabled`.
- **`Timeline`: `color` never reached the resolver.** `<Timeline.Item color="primary">` passed the literal string `"primary"` through to the style.
- **`Highlight`** resolved its wrapped `Text`'s color with its own copy of the lookup, which could land on a different shade than the `Text` inside it.
- **`Overlay` and `LoadingOverlay` could paint under what they covered.** Siblings stack in render order at z-index 0 (react-native-web sets it on every View), so an overlay placed before the content it covers drew beneath it. `LoadingOverlay` at the top of a form left the fields on top of the loader. Overlay now defaults `zIndex` to 1, or to the theme's `overlay` layer when `fixed`, so it covers its siblings wherever it sits. An explicit `zIndex` still wins.
- **`AutoComplete` filled the input with an option's `value`.** Picking "Football" left `football` in the field unless you passed `displayProperty="label"`, which every single-select usage needed. `displayProperty` now defaults to `'label'`.
- **Docs prop tables** dropped the description of any prop whose JSDoc wrapped a `@deprecated` note across lines, and spliced the note's continuation into the description text.
- **`AppShell`: the chrome flashed light on a statically rendered page.** The shell dressed its header, navbar, aside, toc, footer, and bottom bar off the gray ramp behind a `theme.colorScheme` branch. A branch is resolved wherever it runs — in Node, at prerender, where the scheme is always light — so the static markup carried a light hex per chrome surface that no stylesheet could correct, and a dark-mode reader watched the shell sit light until hydration re-ran the branch. Everything around it was already dark at first paint, which is what made it so visible. The steps the shell uses are now published as CSS variables by `createThemeColorVariablesCss`, so the cascade answers the branch before any JavaScript runs. Apps already inlining that stylesheet get the fix with no change; native and apps that have not opted into `colorsAsCssVariables` keep literals. The new `shellChrome` / `shellChromeColors` helpers are exported for app chrome that needs to match.

## Removed

| Removed | Use instead | Where |
| --- | --- | --- |
| `colorVariant` | `color` (`c` on Text) | Text, Button, IconButton, Checkbox, ControlField, Toggle, ToggleGroup, Divider, Timeline |
| `sev` | `severity` | Alert, Toast, and `toast.show({ … })` |
| `tone` / `hoverTone` / `activeTone` | `color` / `hoverColor` / `activeColor` | MenuItemButton |
| `colorScheme` | `color` | Slider, RangeSlider, Joystick |
| `'danger'` | `'error'` | Menu, MenuItemButton |
| `'info'` as a *color* | `'primary'` | still a valid `severity` on Alert / Toast |
| `Notice` | `Alert` | the component and its `Notice*` types |
| `AlertColor`, `ToastColor`, `ProgressColor`, `AccordionColor`, `SliderColorScheme`, `DividerColorVariant`, `MenuTone` | `ThemeColor` | one type, one vocabulary |
| `ProgressWithCompound` | `Progress` | sub-components are attached to it |
| `CodeBlock` `fileName` / `fileIcon` | `files={[{ name, icon }]}` | |
| `DatePickerInput` `withInput={false}` | `<DatePicker>` | |
| `Tooltip` `multiline` | `width` / `maxWidth` | it was already ignored |
| `PhoneInput` `'UK'` | `'GB'` | the ISO 3166 code |
| `BrandIcon` camelCase names, `resolveBrandName` | kebab-case names | e.g. `google-play` |
| `resolveTokenColor` (Button) | `resolveAccentColor` | |

`AudioPlayer` and `BrandIcon` keep `colorScheme` — theirs genuinely means light/dark.

On the text components the prop is `c`, and `color` is gone there — see [Short style props](#short-style-props). `Badge` keeps `c` beside `color` (and `v` beside `variant`); where both are passed, the full name wins.

## Migrating

A codemod ships with the repo:

```
npm run codemod:color-props -- src              # rewrite in place
npm run codemod:color-props -- --dry src        # preview
npm run codemod:color-props -- --check src      # exit 1 if anything is stale
```

It covers `colorVariant`, `sev`, the `tone` family, and `colorScheme`. The rest of the table above is a find-and-replace on a name that appears in few places.

It parses with the TypeScript compiler rather than matching text, so it only touches real JSX attributes and object keys — and it scopes the component-specific renames (`tone`, `colorScheme`) to the components they belong to. Pass `--exclude <fragment>` to skip paths, and it will name any site that sets both spellings rather than guessing which to keep.

## Short style props

Every style shorthand now has exactly one name, the short one Mantine uses. The long spellings are removed, not aliased, so there is one way to write each thing and autocomplete shows it. The color-props codemod does not rewrite these; the tables below are the complete list.

### Text

On `Text`, `Title`, `Highlight`, the H1–H6 / P / Small / … aliases, and every `<Text>` slot prop (`titleProps`, `labelProps`, …):

| Removed | Use | |
| --- | --- | --- |
| `color` | `c` | text color |
| `weight` | `fw` | font weight |
| `fontFamily` | `ff` | font family |
| `tracking` | `lts` | letter spacing |
| `align` | `ta` | text alignment |
| `lineHeight` | `lh` | line height |
| `uppercase` | `tt="uppercase"` | text transform — also `lowercase`, `capitalize`, `none` |
| | `fs` | **new** — font style: `italic`, `normal` |
| | `td` | **new** — decoration: `underline`, `line-through`, `none` |

```tsx
<Text size="sm" fw={600} c="dimmed" tt="uppercase" lts={1}>Section</Text>
```

`size` keeps its name. Like Mantine's `size` on Text, it sets the font size *and* the line height from the theme, and it is the same `size` every other component takes. `fs="normal"` and `td="none"` also undo the `Italic` / `Underline` aliases, and `tt="none"` undoes a text role's caps.

The same names apply wherever another component styles text: `Link` (`c`, `ff`), `RollingNumber` (`c`, `fw`, `ff`), `ShimmerText` (`c`), `DataList.ItemLabel` / `ItemValue` (`c`), and `CodeBlock`, `KeyCap`, `Markdown` (`ff`).

### Box props on every component

`BaseProps`, which every public component's props extend, now carries the box props beside the spacing props. They land on the same root element:

| Prop | Sets |
| --- | --- |
| `w`, `h` | width, height |
| `miw`, `maw`, `mih`, `mah` | min / max width and height |
| `bg` | background: a background token (`'surface'`, `'subtle'`…), a palette name (its subtle tint), `'primary.5'`, or any CSS color |
| `opacity` | opacity |

Sizes take px, a percentage, `'auto'`, `'full'` (100%), or on web any CSS length.

| Removed | Use | Where |
| --- | --- | --- |
| `minW` / `maxW` / `minH` / `maxH` | `miw` / `maw` / `mih` / `mah` | Block, Popover, Menu, Table cells, every component that had them |
| `minWidth` / `maxWidth` (aliases) | `miw` / `maw` | Table cells |
| `minWidth` | `miw` | AutoComplete |
| `inputWidth` | `w` | AutoComplete, TimePickerInput |
| `maxWidth` | `maw` | Toast, FormLayout, `AppShell.Main`, `AppLayout`'s `main` config |
| `width` / `maxWidth` | `w` / `maw` | Tooltip (the bubble) |
| `width` / `height` | `w` / `h` | Wheel, FormField; Tree's `height` → `h` |
| `height` | `h` | Carousel (the slides), DataTable (the table frame) |
| `maxHeight` | `mah` | Spoiler (the collapsed height), ContextMenu |
| `backgroundColor` | `bg` | AppShell, `AppLayout`'s options, Avatar (the circle), BrandButton, QRCode (the code) |
| `backgroundColor` | `trackColor` | Gauge — it was always the track |
| `maxH` | `maxDropdownHeight` | Select — it bounds the dropdown, not the input |
| `width` / `height` / `minWidth` / `maxWidth` / `minHeight` / `maxHeight` | `w` / `h` / `miw` / `maw` / `mih` / `mah` | every chart in `@platform-blocks/charts`, and `ChartGestureSurface` |

Spotlight's `width` and `height` were declared but never read, and are gone; its `maxHeight` stays, since, as in Mantine, it caps the results list rather than the palette.

A few components point a box prop at the part you see as "the component" rather than an outer wrapper: Popover and Menu size their dropdown (`w="target"` matches the trigger), HoverCard its card, Dialog its panel (`w`, `h`), Tooltip its bubble, Avatar and QRCode paint their circle and code with `bg`, TextArea's `h` is the text box, Waveform's and AudioPlayer's `w` / `h` are the drawing, Overlay's `opacity` is the backdrop's alpha (so children stay opaque), and `Table.ScrollContainer`'s `miw` is the scrolled content's width.

### Helpers

`extractSpacingProps` / `useSpacingStyles` / `getSpacingStyles` are now `extractStyleProps` / `useStyleProps` / `resolveStyleProps`, and they handle the box props too. They are exported from the package root with the `StyleProps`, `SpacingProps`, `BoxProps`, and `DimensionProp` types, so a custom component can take the same props: spread `extractStyleProps(props).styleProps` into `useStyleProps` and put the result on its root. `LayoutProps` is now just `fullWidth`. `BaseSystemProps` is gone; use `VisibilityProps`.

## Titles step back from what they label

On a phone, Select and AutoComplete open as a sheet with the field's label above the options, and the title rendered exactly like the options below it: primary color, `md`, semibold. It read as one more option. The same mismatch turned up across the library: RadioGroup's label matched its options, nested Tree headings matched their rows, and the DataTable filter popover's title matched its section labels. Meanwhile, the places that already set their group labels apart each did it differently. Colors ranged over secondary, muted and `info`, sizes over 10–12 px, and weights over 400–600. ControlField.Group's `muted` title sat at about 3.3:1 on white, below AA for 12 px text.

Two theme **text roles** now cover these labels:

| Role | Default | Used by |
| --- | --- | --- |
| `panelTitle` | secondary, `sm`, 600 | the mobile sheet of Select, AutoComplete, DatePickerInput, TimePickerInput, ColorInput and ColorPicker; DrawerNavigator's default drawer title; the DataTable filter popover title |
| `sectionLabel` | secondary, `sm`, 600, uppercase, 0.5 tracking | `Menu.Label` (and so Pagination's "Rows per page" and the DataTable column menu), AutoComplete and Spotlight groups, `ControlField.Group` titles, the DataTable popover's "Search" / "Filters", top-level branches of a `disclosure="nested"` Tree or NavTree |

`sectionLabel` is what AutoComplete group headers and the Calendar weekday row already used, so AutoComplete looks the same.

**Choice labels go regular.** Checkbox, Radio and Switch labels drop from 600 to 400, so a RadioGroup's semibold label now stands above its options instead of matching them. Field labels, including Rating's, stay semibold, and `labelProps.weight` still overrides.

### What changes on screen

| Component | Before | After |
| --- | --- | --- |
| Mobile sheet title (Select and the other pickers) | primary, `md` | `panelTitle` |
| DrawerNavigator default title | primary, `xl` | `panelTitle` |
| DataTable filter popover | title and section labels all primary, 12 px, 600 | `panelTitle` title, `sectionLabel` sections |
| `Menu.Label` | secondary, 12 px, **400** | `sectionLabel`: semibold and uppercase |
| Spotlight groups | `info` at 70% opacity, 11 px, uppercased in JS | `sectionLabel` (the band behind it stays) |
| `ControlField.Group` title | muted, 400 | `sectionLabel` |
| Nested Tree / NavTree headings | same as their rows | `sectionLabel` |
| Checkbox / Radio / Switch label | 600 | 400 |

### Theming it

`theme.textRoles` overrides a role field by field, for every component at once. `color` takes the same vocabulary as the `color` prop. To put the old sheet and drawer titles back and drop the caps:

```tsx
createTheme({
  textRoles: {
    panelTitle: { color: 'primary', fontSize: 'md' },
    sectionLabel: { uppercase: false },
  },
});
```

A theme can also add roles of its own (`textRoles: { eyebrow: { … } }`).

### New API

- `Text` takes `textRole`. The role supplies color, size, weight, tracking and case, and `c` / `size` / `fw` / `lts` / `tt` still win over it.
- `tt="none"` on a `Text` turns off the case its role applies (`tt` replaces `uppercase` — see [Short style props](#short-style-props)).
- `resolveTextRole(theme, role)` returns a React Native text style for a raw `Text`. `getTextRole` returns the merged settings, and `DEFAULT_TEXT_ROLES` holds the built-in values. Types: `TextRoleName`, `TextRoleStyle`, `TextRoles`.
- Slot props for labels that had no way to restyle them:
  - AutoComplete: `groupLabelProps`
  - Spotlight: `groupLabelProps`, and `labelProps` on `Spotlight.ActionsGroup`
  - `ControlField.Group`: `titleProps`
  - `Menu.Label`: `textProps`
  - NavTree: passes `renderLabel` through to Tree

## Charts fit the space they are given

Every chart drew at a fixed size — `width={720}` in the docs, `width = 400` in the source — and a container narrower than that number simply clipped it. On a phone, most of the chart was off-screen.

**Omit `w` and a chart now fills its container**, remeasuring when that container changes. A `w` you *do* pass is honoured up to what the box can give it, so a chart can no longer draw wider than the space it is in:

```tsx
<View style={{ flex: 1, padding: 16 }}>
  <LineChart data={data} h={240} />   {/* as wide as the padded box */}
</View>
```

Four new props tune it: `aspectRatio` (height as a fraction of the resolved width), `maw` / `miw`, and `mah` / `mih`. `maw` is the one radial charts want — it caps a pie or gauge at its natural size in a wide column while still letting it shrink on a phone.

The measurement lives in `withChartAutoSize`, applied at each chart's export, and is exported alongside `useChartAutoSize` so an extension building its own visualisation gets the same behaviour without reimplementing it.

## Margins are measured, not guessed

Every cartesian chart reserved `{ top: 40, right: 20, bottom: 60, left: 80 }` regardless of what it was about to draw. That is a third of the width of a chart in a phone-sized column, and it was still not enough for a category called "Customer Success", which wrapped mid-word inside a 44px label box.

Margins now come from the text that will actually be drawn — tick labels, axis titles, the legend, and the chart title — through `resolveCartesianPadding`, which is exported for extensions building their own axes. A chart labelled `$0`–`$500k` spends less width on its axis than one labelled `1,250,000`, and neither wraps nor clips.

Alongside it:

- **Tick labels no longer wrap mid-word.** Vertical labels stay on one line and ellipsise; horizontal ones take a second line only when the padding reserved for one. "Engineering" was rendering as "Enginee / ring".
- **Axis titles stay on one line.** The title box was pinned at 100px, so "Investment (USD thousands)" stacked into two rotated lines across the plot.
- **Colliding labels are dropped on both axes.** Only the horizontal axis used to thin its labels; a heatmap with 5px rows stacked its day names into a smear.
- **Ticks point away from the plot** on all four edges, instead of always down and to the right — which had put a left axis's ticks *inside* the plot, with each chart cancelling it out in its own offset.
- **A legend pinned to the top starts below the chart title** rather than rendering through it.
- **`estimateChartTextWidth` weights by character class.** A flat per-character average under-reserved for digits and capitals — the characters axis labels are mostly made of — so `$500k` ellipsised inside a box sized for it.

## Axis ticks

- **Tick steps are chosen by proximity, not by rounding up.** A domain of 0–8,800 asked for five ticks got a step of 5,000 and an axis with a single label on it. Both tick generators now share `niceTickStep`, which picks the 1/2/5 × 10ⁿ step closest to the requested density — the same rule d3 uses.
- **No more ticks outside the domain.** `generateNiceTicks` ran half a step past `max`, and the axis drew that label wherever the scale extrapolated to — which is how a `$1000k` label ended up floating above a chart whose data topped out at 820.
- **Charts hand the axis its ticks.** `Axis` accepts `ticks`, so the labels and the gridlines behind them come from one array instead of each deriving its own.
- **A pinned `cellSize` on a heatmap scales to fit** rather than overflowing. Both dimensions scale together, so the cells keep the aspect ratio that was asked for.

The 123 chart demos dropped their hard-coded widths and now demonstrate the responsive default; radial demos pass `maw` instead.

## Large numbers abbreviate

An axis running to 10,000 spent its width on digits and commas, and each chart fell back to its own rendering — `9,000` on a bar chart, `9000` on a combo chart. **Numbers a chart renders without a formatter of its own now abbreviate: `9000` reads `9K`, `1,250,000` reads `1.3M`.** That covers axis ticks, value labels, and gauge and donut center values.

- **A tick label never rounds.** An axis abbreviates only when every tick stays exact — `0 / 2.5K / 5K`, or `1M / 1.05M` once ticks are at least 1,000 apart. A narrow range at a large magnitude, like a price axis stepping `1,200 / 1,210 / 1,220` or an axis of years, keeps the chart's full rendering rather than printing `1.2K` on every tick.
- **Tooltips and accessibility labels keep full values.** They are where a reader goes for the exact number.
- **Opting out is one prop.** `<ChartThemeProvider value={{ numberFormat: 'full' }}>` restores the number rendering each chart had in 1.1.0; a function there formats every chart's defaults your way. A per-chart `labelFormatter` or `valueFormatter` still wins over both.
- **The Heatmap `'compact'` preset abbreviates.** It had been rendering grouped digits.

`formatCompactNumber`, `createTickFormatter` and `useNumberFormatter` are exported for extensions that draw their own labels.

## Sankey labels

A Sankey with more than a handful of nodes was illegible. Node names were drawn *inside* the node rectangle, in white, truncated at ten characters — so "Campus Recruiting" read as "Campus Rec…", a name centred on a 40px node spilled out both sides of it, and any node with a pale fill lost its label into the background entirely.

Labels now sit **beside** the node, in the theme's text colour:

- The first and last columns label outward, into a margin measured from those labels — sources read down the left edge, destinations down the right.
- Everything in between labels toward its own flows, with a halo (the text painted once as a background-coloured stroke, once filled) so it stays readable over any link.
- **Those margins are given up when they get expensive.** On a phone the pair was taking more than half the width and squeezing the diagram into a strip, so below that threshold the first column labels inward like every other column — it points into a gap nothing else wants — and the width goes back to the flows. The right margin is the one kept, because the last column has no gap after it to point into; it also gets a wider cap once it is paying alone.
- Labels are checked for collisions against every other label, not just the ones in their own column, and the bigger node wins. Values are dropped a whole column at a time, so a column never reads "Solar / Wind 32 / Hydro".
- The value follows the name in the secondary colour, and is the first thing dropped when a label runs out of room; the name is truncated only after that.
- Two labels closer together than a line of text no longer print over each other — the lower one is dropped, the same rule the axes use.
- Auto node width moved from 8% of the plot (a 40px slab between every pair of columns) to the d3-sankey range of 10–24px, which is where the width for those labels came from.

## No more `SafeAreaProvider` wrapper

Dialog, the mobile sheet of Select and the other pickers, AppShell and `useDeviceInfo` read the device's safe-area insets from a `SafeAreaProvider`, which every app had to mount above `PlatformBlocksProvider` itself. An app that didn't got zero insets: a fullscreen Dialog drew its header under the notch, and a picker sheet put its last option under the home indicator.

**`PlatformBlocksProvider` now mounts one when none is above it**, so the wrapper can go:

```tsx
// Before
<SafeAreaProvider>
  <PlatformBlocksProvider>…</PlatformBlocksProvider>
</SafeAreaProvider>

// After
<PlatformBlocksProvider>…</PlatformBlocksProvider>
```

It starts from the window's insets on native and from zero on web, so the first frame and statically rendered HTML have content instead of waiting for a measurement. When a provider is already mounted above it — Expo Router mounts one, or you mounted your own — it uses that one and adds nothing. `withSafeAreaProvider={false}` leaves the tree without one.

## Migration notes

- An app with no safe-area provider above `PlatformBlocksProvider` (no Expo Router, no `SafeAreaProvider` of its own) now gets one from `PlatformBlocksProvider`, which wraps the app in a `flex: 1` view. At the app root that changes nothing; if you render `PlatformBlocksProvider` somewhere it shouldn't stretch, pass `withSafeAreaProvider={false}`.
- In such an app, `AppShell withSafeArea={false}` now offsets its content by the insets on phones, as it already did under Expo Router.
- `Text` renders `c="success" | "warning" | "error"` one shade further from the surface than in 1.1.0. This is the fix for the `c`/`color` split; if you were relying on the old shade, `c="success.5"` reproduces it exactly.
- `ControlFieldContextValue.colorVariant` and `ToggleGroupContextValue.colorVariant` are gone. Both contexts now carry a single `color` with the alias already folded in. These are internal context shapes, not component props.
- `CheckboxStyleProps.colorVariant` is gone; it was already unused.
- `AutoComplete` writes the selected option's `label` into the input, not its `value`. Pass `displayProperty="value"` to keep the 1.1.0 behavior. `onSelect` still receives the whole option.
- `Overlay` and `LoadingOverlay` render with `zIndex: 1` by default (the theme's `overlay` layer, 1300, when `fixed`). If a sibling was meant to sit above an overlay, give it a higher `zIndex`.
- `'info'` and `'danger'` no longer resolve as colors. They were spellings of `primary` and `error` with nothing extra behind them. `severity="info"` is unaffected — Alert and Toast map it to the primary palette themselves.
- A theme that defines its own `info` or `danger` palette still works: `color="info"` finds it by name like any other palette.
- `SwitchStyleProps.color` is `ThemeColor` rather than `ColorValue`. Both are string types; the change is completion, not compatibility.
- Charts without an explicit `w` now fill their container instead of drawing at 400px. Pass `w` (or `maw`) where a chart is meant to stay small — a sparkline in a table cell, say.
- Cartesian charts draw more plot and less margin at the same `w`/`h`, because the margins are now measured. Screenshot tests over charts will need new baselines.
- An explicit `w` now wins over `fullWidth` everywhere. On `Block` it was the other way round, and `<Column w={240}>` — `Column` is `fullWidth` by default — was stretched to 100%.
- `bg` resolves the same way on every component, so a bare palette name is its subtle tint. `Avatar` and `BrandButton` used to paint the vivid shade for `backgroundColor="primary"`; write `bg="primary.5"` for that.
- Components that ignored the box props now honor them: `Overlay` dropped `w` / `h` / `bg` and the min / max sizes, `WaveformSkeleton` dropped every style prop, and `Select` ignored `mah`.
- `Toast` with `maw` above 400 grows to it; before, `maxWidth` capped a toast outside the provider at 400 whatever you passed.
- `Skeleton w={0}` is zero wide rather than falling back to the shape's default.
- On `Table` cells, `miw` / `maw` now apply alongside an explicit `w`; they were dropped when `w` was set.
- Axis ticks and value labels abbreviate large numbers by default (`9K` rather than `9,000`). Wrap charts in `<ChartThemeProvider value={{ numberFormat: 'full' }}>` to keep the 1.1.0 number rendering.
- `getColor` from `core/utils` is documented as **web only** — it returns a `var(--platform-blocks-color-…)` reference, which is inert on native. It is unchanged; use `resolveColorProp` for a concrete color on every platform.

## Install

```bash
npm install @platform-blocks/ui@1.2.0 @platform-blocks/charts@1.2.0
```

No new peer dependencies, and no change to the Expo SDK 57 / React Native 0.86 baseline from 1.1.0.
