# 1.0.0

The first stable release. Everything since 0.11.0 was aimed at one goal: making the public API something we're willing to keep. That meant finishing the systems that were half-built, deleting the props that were declared but never wired up, and replacing the last hand-rolled subsystems with ones that have a single owner.

This release also carries everything from 0.11.0, which was tagged but never published to npm — if you're coming from 0.10.1, see [0.11.0](0.11.0.md) for that half of the changes.

Three efforts define this release:

- **An elevation system.** `Surface` plus a `theme.surfaces` ladder replaces per-component background/border/shadow guesswork. Card, Menu, Popover, Dialog, Toast, ListGroup, Select, Search, Stepper, EmojiPicker, ColorPicker, CodeBlock and Blockquote all resolve their chrome through it.
- **A real icon set.** The 1,300-line hand-drawn SVG registry is gone, replaced by a Tabler-backed registry. All 204 existing icon names still resolve, and `Icon` now takes any icon library directly.
- **Motion and contrast as system concerns.** A `transitionDuration` prop on ~15 components, resolved through one hook that honors reduced-motion, and a refreshed default palette that the contrast tests validate across every theme × color × variant combination.

There are breaking changes — a new required peer dependency, a palette change, and removals of never-implemented chart props — all collected under **Migration notes**.

## Platform

Expo SDK 57 / React Native 0.86, Reanimated 4.5, Worklets 0.10. The library is developed and tested against `~57.0.0` of the `expo-*` optional peers (`expo-audio`, `expo-haptics`, `expo-linear-gradient`, `expo-document-picker`, `expo-status-bar`); their declared peer ranges stay permissive floors, so older SDKs still install without warnings.

## Elevation: `Surface` and `theme.surfaces`

Components used to reach into `theme.backgrounds` and pick a shadow independently, so a popover could end up with a level-3 shadow over a level-0 fill, and nesting a card inside a panel inside a sheet produced whatever each component happened to hardcode.

`SurfaceLevel` is a four-step ladder — `0` page, `1` resting content, `2` transient content floating over it, `3` content that takes over the screen — and one `SurfaceToken` (`background`, `border`, `shadow`) resolves per level. Elevation reads differently per scheme: light mode conveys it mostly with shadow, dark mode mostly with a lighter fill and a hairline border, and the ladder encodes that instead of every component re-deciding.

```tsx
<Surface level={1} padding="md" radius="md">
  <Surface raised>…</Surface>   {/* level 2, derived from the parent */}
</Surface>
```

- **`raised`** takes the enclosing surface's level and adds one (clamped at 3), so a popover inside a card lands a step above the card without either one naming a number.
- **`withBorder`** defaults to `'auto'` — drawn in dark mode, omitted in light.
- **`bg`**, **`borderColor`**, **`borderWidth`**, **`padding`** override individual pieces, and the full spacing / layout / radius / shadow prop families are supported.
- **`useSurfaceLevel()`** reads the current level, for components that need to nest correctly without rendering a `Surface`.

`theme.surfaces` is **optional**. A theme that doesn't define it gets a ladder derived from its existing `backgrounds` (`base` → `surface` → `elevated`), filled in per field, so every custom theme keeps working untouched.

## Icons are Tabler-backed

`Icon`'s registry was ~1,300 lines of inline SVG path data across six files. It is now generated from [`@tabler/icons-react-native`](https://tabler.io/icons), which becomes a **required peer dependency**.

**All 204 previously registered names still resolve** — the new registry has 216 entries and is a strict superset, with both the historical camelCase names (`arrowDown`) and kebab-case aliases (`arrow-down`). Existing code doesn't change.

What's new:

- **Any icon library works directly.** `<Icon icon={IconRocket} />` or `<Icon icon={<IconRocket />} />` — no registration step.
- **`variant="filled"`** picks the filled glyph, falling back to outlined where none exists.
- **`registerIcon` / `registerIcons`** accept component-based definitions (`{ outlined, filled }`) alongside the legacy SVG-path form.
- **`semanticIcons`** maps `info | success | warning | error` to registry names, so `Alert` and `Toast` stay consistent and can be re-themed in one place.

`BrandIcon` is unaffected and remains the home for logo glyphs; it now also exports `brandIcons` and `resolveBrandName`.

## Refreshed default theme

The default palette moves off the iOS system colors onto a neutral, contrast-validated set:

| Token | Was | Now |
|---|---|---|
| `primaryColor` | `#007AFF` (iOS blue) | `#3B82F6` |
| `secondary` | lavender ramp (`#9B9BCF`) | slate ramp (`#64748B`) |

Every palette was re-stepped to a 10-shade ramp with even perceptual spacing, and the `variantContrast` suite walks every theme × color × variant combination asserting the resolved text clears a legible ratio. Apps that set their own `primaryColor` / palettes are unaffected; apps on the default theme will look different.

## Motion

New **`transitionDuration`** prop (milliseconds) on `Accordion`, `AppShell`, `Button`, `Carousel`, `Checkbox`, `Collapse`, `Dialog`, `IconButton`, `KeyCap`, `Progress`, `Radio`, `Switch`, `Tabs`, and `Toast`.

All of them resolve it through `useTransitionDuration`, which returns `0` when the prop is `0` **or when the user has reduced-motion enabled** — and `0` means "apply the end state immediately", not "run a zero-length animation". Reduced-motion is honored once, in one place, instead of per component.

## New components

- **`Alert`** — the status/severity callout, replacing `Notice`. `variant` (`filled | light | outline | subtle`), `color`, `sev` (`info | success | warning | error`, which sets both the color and the default icon), `title`, `icon`, `withCloseButton` / `onClose`, `fullWidth`, and `titleProps` / `bodyProps` for text overrides. **`Notice` is kept as an alias** — see Migration notes.
- **`Surface`** — see above.
- **`ControlField` / `ControlFieldGroup`** — a labeled, pressable row wrapping a checkbox, radio, or switch, with `label`, `description`, `error`, `isRequired`, `indicatorPosition` (`left | right`), and a `control` slot for a custom indicator. Props accept both the library's short names (`checked`, `disabled`, `required`, `onChange`) and the long forms (`isSelected`, `isDisabled`, `isRequired`, `onSelectedChange`). `ControlFieldGroup` handles the shared surface and grouping; `useControlField` / `useControlFieldContext` / `useControlFieldGroup` expose the state.

## Compound `Progress`

`Progress` gains a compound form for multi-segment bars, alongside the existing single-value API:

```tsx
<ProgressRoot value={72} orientation="horizontal">
  <ProgressSection value={40} color="success" />
  <ProgressSection value={32} color="warning" striped />
  <ProgressLabel>72% complete</ProgressLabel>
</ProgressRoot>
```

The single-value `Progress` also gains form-field affordances (`label`, `description`, `error`, `required` / `withAsterisk`, `labelPosition`, `labelGap`, `labelProps`, `descriptionProps`), interaction props (`onPress`, `onHoverIn` / `onHoverOut`, `onFocus` / `onBlur`), and presentation props (`orientation`, `length`, `trackColor`, `striped`, `animate`, `radius`, `tooltip`).

## A unified `tooltip` prop

`resolveTooltipProps` and `getTooltipText` are exported, and the `tooltip` prop on `Button`, `IconButton`, `CopyButton`, `Slider`, `Progress`, and `DataTable` columns now accepts either form:

```tsx
<Button tooltip="Copy" />
<Button tooltip={{ label: 'Copy', position: 'right', withArrow: true }} />
```

Each host's own legacy props (e.g. `tooltipPosition`) act as defaults and always lose to explicit config keys. `Tooltip` itself gains `maxWidth` and `lineClamp`, and exports `TooltipConfig` / `TooltipPropValue`.

## Overlay positioning

`positioning-enhanced` was reworked around two ideas:

- **Edge pinning.** Vertical placements now return the viewport edge to pin to plus a distance, rather than only an absolute `y`. A dropdown below its trigger pins its `top`; one above pins its `bottom`. Content grows and shrinks *away* from the trigger, so an AutoComplete list filtering down as you type no longer walks the whole popover around the screen, and a mismatch between estimated and measured height no longer shows up as a first-paint jump.
- **`estimatedHeight`.** Callers that know their size up front (a dropdown's `maxH`, or row height × option count) pass it, so the pre-measure and post-measure passes reach the same side and the popover never flips after paint.

Placement is now stateful, with hysteresis on `currentPlacement` so a popover near a boundary doesn't oscillate. The LRU position cache was removed — it predated per-frame scroll repositioning and could resurrect a side the popover had already flipped away from; the math is a couple dozen arithmetic ops, cheaper than building the cache key. The cache-clearing export is kept as a no-op since it was public.

## Component rewrites

- **`Tree`** was rebuilt around a flattened row model (`TreeRow`, `TreeRenderNode`, `useTreeState`, `treeUtils`) instead of recursive rendering. New: **`virtualized`** + `height` for large trees, **`loadChildren`** with `hasChildren` for async/lazy branches, **`keyboardNavigation`**, **`showGuides`**, **`size`**, `renderEndSection`, `rowStyle`, `defaultExpandedIds` / `onExpandedIdsChange`, `autoExpandOnFilter`, `selectionColor`, and full `posInSet` / `setSize` / `ancestorLines` accessibility metadata. `TreeNode<T>` and `TreeProps<T>` are now generic over `data`, and `TreeCheckState` is exported. Existing callbacks (`onToggle`, `onNodePress`, `onSelectionChange`, `onCheckedChange`, `onActiveNodeChange`, `onNavigate`) keep their shapes.
- **`CodeBlock`** moved off the monolithic implementation onto a split `prism` / `header` / `styles` module set, and gained **multi-file tabs**: `files` (`CodeBlockFile[]` with `name`, `code`, `language`, `icon`, `highlightLines`), `defaultFile` / `activeFile` / `onFileChange`, plus `radius` and `withBorder`. `highlightLines` now accepts numbers as well as range strings.
- **`Knob`** gained a variant and behavior vocabulary: **`variant`** (`default | minimal | digital | retro | studio`) supplies form — stroke weights, caps, whether the body is filled, arm vs. dot — while leaving color to the theme, and merges *under* any explicit `appearance` so single properties stay overridable. **`behavior`** (`level | stepped | endless | dual | status`) covers the interaction models. Also new: `tapToSet` (+ `tapDeadRadiusRatio`), full keyboard support via `useKnobKeyboard`, ring `segments` / `segmentMode`, configurable tick sources (`marks | steps | values | count`) with function-driven tick colors and `activeMode` (`fill | nearest`), and a `size` token scale. Exports `KnobVariant`, `KnobBehavior`.
- **`PhoneInput`** now reports change metadata: `onChange(raw, formatted, meta)` where `meta` carries `country`, `dialCode`, `trunkPrefix`, and `isComplete`. Adds `defaultCountry`, `onCountryChange`, `selectableCountry`, `textInputProps`, and `defaultValue`; `country` is typed as `PhoneCountryCode` but still accepts any string.
- **`Rating`** takes **`icon` / `emptyIcon`** as a registry name, an icon component, or an element (`RatingIcon`), plus `clearable`, `disabled`, `required`, `error`, `description`, and `getTooltipLabel`.
- **`DataTable`** replaces the column-settings panel with inline per-column filtering (**`showColumnFilters`**, `ColumnFilterInput`), and column `tooltip` accepts the full tooltip config.
- **`Stepper`** had its layout rebuilt so the steps actually connect. Each step now owns the connector half on either side of its indicator, so horizontal steps sit in equal-width columns with the line running indicator-edge to indicator-edge on the same axis (it used to float at the vertical center of the whole step and stop short of the next circle), and vertical connectors stretch to meet the next indicator instead of drawing a fixed stub. Consumer `icon` / `completedIcon` elements and the `loading` spinner are tinted to read against a filled indicator, upcoming step labels recede, connector thickness scales with `size`, and step numbering follows step order rather than raw child order — so conditional children and `Stepper.Completed` no longer skew it.
- **`Button`**'s style resolution collapsed from `defaults.ts` + `tokens.ts` + `styles/resolver.ts` into a single `styles.ts` and `animation.ts`. `variant` gains `'default'`.
- **`BrandButton`** absorbed `AppStoreBadge` — the same component now renders either a single-line brand button or a two-line store badge, for every brand in the icon registry (see **Migration notes**).
- **`TimePicker` / `TimePickerInput`** — `onChangeComplete` and `columnHeight` on the picker; the input gains the full field vocabulary (`size`, `value` / `defaultValue` / `onChange`, `allowInput`, `panelWidth` / `inputWidth`, `label` / `description` / `error` / `helperText`, `onOpen` / `onClose`, `autoClose`, `clearable`, `fullWidth`, `labelProps` / `descriptionProps`, `startSectionProps` / `endSectionProps`).

## Charts

- **A CVD-safe categorical palette.** `paletteDefaultLight` / `paletteDefaultDark` are eight hues whose *slot order* is the color-vision-deficiency safety mechanism: every adjacent pair clears the hard gates on both the light (`#FFFFFF`) and dark (`#1C1C1F`) chart surfaces (worst adjacent CVD ΔE ≈ 9.1 light / 8.4 dark in OKLab ×100). Slots past #3 can't clear the all-pairs floor, so scatter/bubble usage should fold extras into "Other" or facet rather than cycle. `./colors` is now exported from the package root, and the palettes are validated by a new `chartThemePalette` suite.
- **`PieChart`, `RadarChart`, `HeatmapChart`, `StackedAreaChart`, `StackedBarChart`, `ViolinChart`, `RidgeChart`, `HistogramChart`, `ScatterChart`** were moved onto the shared frame/hit-test/pointer engine introduced in 0.11.0, finishing that migration.
- **Demo data was extracted** out of every demo component into sibling `data.ts` modules, so the docs-site code samples show the chart usage rather than several hundred lines of fixture.
- **Dead props removed** — see Migration notes.

## Docs and tooling

- **`@platform-blocks/react-ui-library/snack`** is a curated secondary entry point. The main barrel bundles to ~2 MB, which Expo's Snackager won't finish building; the snack entry re-exports a subset from individual module paths so the graph stays small enough, which is what the site's "Open in Snack" buttons depend on. Components that statically pull heavy packages (`DataTable`, `Masonry`, `Carousel`, `ShimmerText`, `Waveform`, `Video`, `BrandButton`) are excluded; `CodeBlock` and `FileInput` are included because they resolve their heavy dependencies at runtime through `optionalModule`.
- **`ui:exports` / `ui:exports:check`** generate and verify the package `exports` map (105 components), and `verify:packages` now runs the check first, so a new component can't ship without its subpath export.
- **The docs site was consolidated.** The `/installation`, `/docs/installation`, `/platforms`, `/icons`, `/examples`, `/keyboard`, `/theming`, `/roadmap`, and `/support` routes were removed; installation now lives in `/getting-started`, and the component/chart/hook pages are the reference. New: per-route SEO metadata (`config/routeSeo.ts`), a canonical-alias hook for future duplicate routes, "Try in Expo Go" buttons with Snack QR codes, and a rebuilt home page.

## Migration notes

**`@tabler/icons-react-native` is a new required peer dependency.** `Icon` is exported from the package root and statically imports the registry, so it must be installed:

```bash
npx expo install @tabler/icons-react-native
```

No icon names changed — this is an install-time change only.

**The default theme palette changed.** `primaryColor` is `#3B82F6` (was `#007AFF`) and `secondary` is a slate ramp (was lavender). To keep the old look, set them explicitly on your theme.

**`Notice` is now an alias of `Alert`.** `Notice`, `NoticeProps`, `NoticeVariant`, `NoticeColor`, and `NoticeSeverity` all still export and behave identically — they're deprecated aliases and will be removed in a future major. Rename imports to `Alert` / `AlertProps` / etc. when convenient.

**Calendars size to their grid instead of stretching.** `Calendar`, `MonthPicker` and `YearPicker` used to fill their container, which fanned the seven day columns apart and made a calendar in a wide card read as an awkwardly long block. They now take the natural width of the grid (7 cells plus gaps — 248px at `size="md"`, scaling with `size`, `withCellSpacing` and `numberOfMonths`) and cap at `100%` of the container. Because the width is explicit, a parent's `alignItems` now positions them: use `alignItems: 'center'` to center one. Pass **`fullWidth`** for the old stretch behavior. `Calendar`'s year view also switched to short month labels (`Jan`, `Feb`) so they fit the narrower grid.

**`DataTable`'s column-settings panel was removed.** `onColumnSettings` is gone; use `showColumnFilters` for inline per-column filtering, and `enableColumnReordering` / `columnOrder` / `onColumnOrderChange` (added in 0.11.0) for column arrangement.

**`AppStoreBadge` merged into `BrandButton`.** Two components were drawing the same brand mark from the same registry and disagreeing about everything else — `AppStoreBadge` couldn't be a button, `BrandButton` couldn't be a badge, and `BrandButton`'s `brand` prop was a hand-kept list of 21 platforms while the badge accepted all 44 in the icon registry. `BrandButton` now does both: pass `primaryText` / `secondaryText` and it renders the two-line store-badge shell; omit them and it's the single-line brand button it always was. `brand` accepts every name in the icon registry for both layouts, and universal props (`lightHidden`, `darkHidden`, `hiddenFrom`, `visibleFrom`) now work on badges too.

```tsx
// was
<AppStoreBadge brand="app-store" primaryText="Download on the" secondaryText="App Store" />
// now
<BrandButton brand="app-store" primaryText="Download on the" secondaryText="App Store" />
```

**Charts — removed props.** Most of these were declared in types but never wired to an implementation; removing them makes the types honest.

|---|---|

Behavior should match the charts already migrated in 0.11.0, but custom `renderEntry` / `customTooltip` implementations on these nine are worth re-checking.

## Install

```bash
npm install @platform-blocks/react-ui-library@1.0.0 @platform-blocks/charts@1.0.0
npx expo install @tabler/icons-react-native
```

The API in this release is the one we intend to keep — from here, breaking changes wait for a major.
